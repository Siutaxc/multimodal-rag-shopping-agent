# 阶段 6：有界导购 Agent 与证据回答

## 范围

阶段 6 在冻结阶段 3～5 检索数据集、报告、Provider 和硬过滤契约的前提下，新增自然语言条件解析、最多四步的有界状态机、Redis 会话条件、商品对比、结构化证据包、引用校验、模型超时降级、开发轨迹和导购 UI。

本阶段不包含开放式自主 Agent、支付下单、任意 SQL/代码执行、任意 URL/文件访问或无限工具循环。所有通信继续使用 HTTP/HTTPS，不使用 WebSocket。

## 条件解析与确定性过滤

`RuleConstraintParser` 和可选 Agent 模型 Provider 只能输出 `ParsedTurn`：

- 意图：推荐、搜索、对比；
- 白名单硬条件：类型、品牌、价格区间、币种、无线、ANC、最低续航、最高重量、颜色、音频编码和防水等级；
- 软偏好、需清除字段、全部重置和最多四个商品 ID。

模型输出必须通过 Pydantic 严格 Schema，未知字段被拒绝。解析结果经会话合并后转换成 `ProductFilters`，再由 SQLAlchemy 参数化表达式执行。模型不生成 SQL，也不判断数据库商品是否满足硬条件。

默认 `fixture` Agent Provider 是确定性离线替身：条件解析复用规则解析器，回答阶段只选择证据 ID。可选 HTTP/HTTPS Provider 只返回结构化解析或证据选择 Schema；商品描述与评论以 `untrusted_evidence_data` 传递，不作为系统指令。

模型解析失败或超时时回退到规则解析器。价格规则要求明确的价格上下文或货币单位，避免把“续航至少 7 小时”等表达误识别为最低价格。

## 有界状态机与白名单工具

工具策略完全由代码决定，模型不能添加、改名或重排工具。单次请求最多四步，当前流程最多观测到三步：

1. `get_query_context`：仅在携带不透明 `session_id` 时读取当前会话；
2. `search_catalog`：复用阶段 4 文本检索或阶段 5 图文检索；
3. `get_product_detail`：一次加载最多四件商品的事实与评论；
4. `compare_products`：对 2～4 件商品加载统一字段。

推荐流程通常为“检索 → 详情”，有历史会话时前置上下文读取；显式商品对比通常为“上下文 → 对比”。预算等条件可继承、由最新明确值覆盖、按字段清除或全部重置。不同随机 UUID 会话互不合并。

会话和开发轨迹使用 Redis TTL 存储。Redis 写入失败不会抹掉已取得的确定性商品结果，响应会记录显式降级。生产环境关闭轨迹读取端点。

## 证据与回答约束

每件候选形成结构化证据包：

- 商品事实：标题、品牌、类型、价格、币种、价格快照、无线、ANC、续航、重量、颜色、编码、防水和麦克风；
- 评论证据：来源、评论 ID、主题、摘录、评分和时间；
- 缺失事实也生成 `available=false` 的证据项，因此“暂无可靠数据”可审计。

模型最多选择证据 ID，不能直接写价格或参数。最终回答、商品卡、匹配条件和对比表由确定性代码从商品记录渲染。引用校验检查证据存在、证据属于当前商品、对比字段一致且推荐引用集合完整；失败时用价格事实生成安全回退计划。

评论摘录在响应中明确标记 `untrusted_content=true`。口碑理由只描述“有一条带来源的用户评价涉及某主题”，并引用评论证据，不把评论包装成官方参数。

## HTTP 与 UI

- `POST /api/v1/assistant/query`：自然语言/可选图片 Agent 入口；
- `POST /api/v1/products/compare`：2～4 商品结构化对比；
- `GET /api/v1/sessions/{id}`：读取当前会话有效条件；
- `GET /api/v1/traces/{trace_id}`：非生产环境读取完整 Agent 轨迹。

首页默认展示 Agent 导购模式，同时保留阶段 3～5 的纯文本、纯图和图文检索入口。页面直接渲染结构化商品卡、会话条件、证据链接、状态机、工具步骤、引用校验和降级原因，不从自然语言答案反向解析商品。

## 评测

运行：

~~~powershell
npm run eval:agent
~~~

数据集 `evals/datasets/stage6_agent_cases.json` 包含 15 个多轮推荐、条件覆盖/清除、会话隔离、对比和注入式文本场景。报告输出到 `evals/reports/stage6-agent-evidence.{json,md}`。

默认 Fixture 报告只证明有界编排、证据约束和工程链路；不代表真实 LLM 解析或生成质量。真实 HTTP Agent Provider 已通过 Schema、HTTP-only 和超时契约测试，但尚无可用外部端点实测。
